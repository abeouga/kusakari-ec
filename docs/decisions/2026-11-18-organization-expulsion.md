# 店舗の担当から外すことと、組織からの除名（#166、#177）

## Context

#104 では、店舗の担当者を組織から外しても店舗側のアカウント（`SHOP_STAFF`）のまま残り、購入者（`USER`）には自動で戻らないと決めていた。組織から外す操作そのものは作っていなかった。

その後 #153 で、組織に所属しない担当者は存在しないので、組織から外す操作は「除名」になると決まった（#166 に引き継ぎ）。#153 の案A（`organization_members` の行だけを消して `SHOP_STAFF` のまま所属なしで残す）と案C（`USER` に戻す）は採らない。除名の細部は #167・#168・#170・#173 で決め、残りの食い違いは #177 で決めた。実装は #178・#175・#179・#169・#180。

この記録は、店舗の担当から外す場合と組織から除名する場合の違いと、除名の扱いをまとめる。

## Decision

### 店舗の担当から外す（`DELETE /api/seller/accounts/{memberId}/stores/{storeId}`）

- できるのはオーナーと ORG_ADMIN。外す前に確認のダイアログを出す（#168）。
- 店舗の担当（`store_members`）の行だけを消す。組織への所属（`organization_members`）は残り、ログインもできる。
- 本人に「店舗の担当から外れました」という本人あての通知を送る（#169）。
- どの店舗にも所属していない担当者は、店舗専用ページで自分あての通知だけを見られる。メニューは「出店者通知」だけになり、ほかの画面を開くと案内と通知の画面へ戻るリンクだけが出る（#169）。担当者が見られる通知は、本人あての通知と、今所属している店舗あての通知だけ（`notifications.kind`・`store_id`、V5）。
- オーナーと ORG_ADMIN は、担当者の画面の「表示する人」を「どの店舗にも所属していない人」にして探し、また店舗の担当にできる。初めはロールなしで所属する（#168）。復帰用の招待キーは作らない。

### 組織から除名する（`POST /api/seller/accounts/{memberId}/expulsion`）と復帰（`DELETE` 同 URL）

- できるのはオーナーと ORG_ADMIN（#167・#177。#105 の「オーナーだけ」を改めた）。オーナー本人と、操作している自分自身は除名できない。ORG_ADMIN が別の ORG_ADMIN を除名できる。
- 除名はデータを消さない論理削除で、`organization_members.expelled` を立てる（#173）。会員（`members`）の `enabled` は運営による停止と本人の退会に使っているので、除名には使わない。所属・担当・ロールの行は残し、復帰したら除名前の店舗とロールに戻る。除名中は担当・ロール・ORG_ADMIN を変えられない（409）。
- 除名した人はすぐにログインできなくなる。Cognito のユーザーは消さず、`AuthService.current()` が除名中の担当者を 403 `ACCOUNT_EXPELLED` で止める。ログイン中の人は次の要求でセッションが終わり、ログインフォームに「このアカウントは無効化されています。組織の管理者にお問い合わせください。」と出る。本人には通知しない（#168）。
- Kusakari Canvas はログインの確認を EC の `/api/auth/me` に問い合わせるので、除名した人は Canvas でも使えなくなる。Canvas 側の変更はない（#177）。
- その人が発行した招待キーは取り消す。キャンセル・返金の操作者や通知の記録は残す（#153 の項目5・6）。
- 除名した人は、担当者の画面で既定では表示せず、「表示する人」を「除名した人」にして出す。MANAGER には出さない（#173）。

### 操作の記録（`organization_member_events`、V4）

- 店舗の担当にする（`ASSIGN_TO_STORE`）・外す（`REMOVE_FROM_STORE`）・組織から除名する（`EXPEL_FROM_ORGANIZATION`）・復帰させる（`REINSTATE_TO_ORGANIZATION`）を、操作した人・操作された人・日時とともに記録する（#170）。ロールの変更だけのときは記録しない。
- 担当の出入りには店舗を入れ、除名と復帰では空にする（#177。#170 の「店舗は残さない」を改めた）。店舗がないと、外された後の人の記録がどの店舗のものか判定できず、履歴を店舗ごとに絞り込めないため。
- オーナーと ORG_ADMIN は、店舗専用ページのサイドバーの「履歴」で、除名と復帰は組織の全件、担当の出入りは選んでいる店舗の分を見られる（#180）。操作された人が除名されていても記録は消さない。

## Alternatives

- 組織から外した人を `SHOP_STAFF` のまま所属なしで残す（#153 の案A）、`USER` に戻す（案C）：組織に所属しない担当者を作らないため、どちらも採らない。
- 除名で Cognito のユーザーを無効にする・消す：復帰させられなくなる（消した場合）か、運営の操作と混ざる。アプリ側で止めた（#173）。
- `members.enabled` で除名を表す：運営による停止と本人の退会の意味と混ざる。除名は組織側の出来事なので、組織への所属に持たせた（#173）。
- 除名中の状態を記録のテーブルから読む：履歴から今の状態を取り出す流れになる（#173）。
- ログイン中の除名された人に、専用の画面を出し続ける：既存の無効なアカウント（`ACCOUNT_DISABLED`）と同じく、次の要求でセッションを終わらせ、ログインフォームで理由を出す形にそろえた。
- 通知に店舗の列だけを足し、店舗のないものを本人あてとみなす：V5 より前の店舗あての通知が、どの店舗にも所属していない人にも見えてしまうため、種別の列も足した。

## Consequences

- V5 より前の担当者あての通知は、店舗あて（`kind = 'STORE'`）にしたが店舗が分からないので、どこかの店舗に所属している間だけ見られる。
- 店舗の閉鎖で担当が自動で外れるとき（#79）は、操作した人がいないので記録も本人への通知もしない。
- オーナーを別の人に譲る仕組みはまだない（#181 で決める）。オーナーは除名できないので、オーナーを替えるにはその仕組みが要る。
- 担当者の表は店舗の数だけ横に長く、「組織からの除名」の列は横に送らないと見えないことがある。
