# 店舗受け取りの連絡先と受取店舗

## Context

商品の受け取りは、購入者が店舗へ行く店舗受け取りだけに決まっている（issue #11）。配送はしない。

受け取りに関わる形は、次の3つの決定で今の形になった。

- 2026-10-23：受取連絡先（受取人・電話番号・連絡先メール）を、カートごとではなく会員アカウントに保存する。カート画面で毎回入力し直す必要があったため。
- 2026-11-05：注文・受け取りのどこからも使われていなかった住所管理（画面・API）を削除する。
- 2026-11-09：カート全体で1つの受取店舗を選ぶ形をやめ、商品を販売している店舗で受け取る（issue #70）。選んだ受取店舗が、商品の在庫がある店舗と関係なく受取場所になっていたため。

その後、DB の構成 v3（[DB 構成 v3 の決定](2026-11-11-db-v3.md)）で、商品は1つの店舗に属し、カートは店舗を持たない形に作り直した。この記録は、今の実装に合わせて3つの決定を1つにまとめたものである。

## Decision

### 受取連絡先

- 受取連絡先は会員アカウントに1件だけ保存する（`member_pickup_contacts`、会員 ID が主キー）。API は `/api/account/pickup-contact` の GET / PUT / DELETE で、画面は「アカウント設定 > 受取連絡先」（`/account/pickup-contact`）に置く。
- カートの表示と注文確定は、カートを持つ会員の受取連絡先を読んで使う（`DeliveryService.pickupDetails`）。連絡先がなければ空として扱う。
- 注文確定のときに、その時点の連絡先を注文（`orders.recipient_name`・`recipient_phone`・`contact_email`）に写す。
- 住所（郵便番号・住所）は扱わない。住所管理の画面（`/account/address`）と API（`/api/account/address`）はなく、DB にも住所の表はない。

### 受取店舗

- 受取店舗は、商品を販売している店舗（`products.store_id`）である。購入者はカートで受取店舗を選ばず、変えることもできない。カートに受取店舗の欄や「変更」ボタンはない。
- ヘッダーの「店舗を探す」は店舗の案内（一覧と店舗の紹介ページ）で、受取店舗を選ぶ操作ではない。
- 注文確定は、受取店舗ごとに1件の注文を作る。注文の保存・在庫の減算・明細の保存は1つのトランザクションで行い、カート、店舗（ID の順）、組織、商品、在庫の順にロックする。同じ `requestId` の再送は同じ注文群を返す（一意キー `uk_orders_request (cart_id, request_id, store_id)`）。`POST /api/orders` の応答は `{ "orders": [...], "payment": ... }` である。
- 注文確認は、受取店舗ごとに店舗の情報と商品をまとめて表示する。注文完了と注文履歴は、注文ごと（＝受取店舗ごと）に店舗名を表示する。店舗名・住所・営業時間は注文に写して保存する（`orders.store_name`・`store_address`・`store_business_hours`）。

## Alternatives

- 受取連絡先をカートに保存したまま表示だけ変える：注文ごとの連絡先がカートに依存し続けるため採らない。
- 住所の項目に受取連絡先を足す：住所（郵便番号・住所）と店舗受け取りの連絡先は意味が違うため採らない。
- 住所管理の画面だけを隠して API を残す：使われない入力口が残り続けるため採らない。
- 1件の注文に店舗の違う明細を入れ、明細に店舗を持たせる：受け取り準備・受け渡し・キャンセルは注文単位なので、ある店舗の操作が別の店舗の商品の状態まで変えてしまう。採らない。
- 受取店舗を注文のときに決める：カートで見た価格・在庫と、注文のときの店舗が食い違うため採らない。

## Consequences

- 注文を確定した後にアカウントの受取連絡先を変えても、確定済みの注文は変わらない。
- 1回のお会計で複数の店舗の商品を買うと、注文が店舗の数だけできる。店舗の業務（受け取り準備・受け渡し・キャンセル・通知・注文実績）は注文ごとに行う。
- 試験：`e2e/business-pickup-store.spec.js` で、2店舗の商品を入れたカート、店舗ごとの注文確認、2件の注文、各店舗の在庫の減算、`orders.store_id`、再読み込み後の注文履歴を確かめる。`e2e/business-account-no-address.spec.js` で、住所管理がないことと、ほかのアカウント設定が開けることを確かめる。
