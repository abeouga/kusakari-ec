# 未ログイン時のカート利用（ゲストカートの廃止）

Issue #10。2026-11-09 決定。旧 `docs/guest-cart.md` を置き換えます。

## Context

ゲストカートは未ログインの選択をReactのメモリーだけに保持していました。再読み込みや、通知のリンクから全画面遷移したときに商品が消え、利用者には不具合に見えていました（Issue #10）。ログイン後に会員カートへ取り込むため、認証必須の `PUT /api/cart/guest-items` と、取り込み失敗時の再試行画面も持っていました。

## Decision

- カートはログインした会員だけが使います。カートの正本は従来どおりMySQLの会員カートです。
- 未ログインで商品一覧・商品詳細の「カートに追加」を押すと、カートを変更せずに専用ログイン画面（`/account/login?returnTo=…`）へ移動します。
- 未ログインでヘッダーのカートボタンを押す、または `/cart` を開くと、カートを表示せずに専用ログイン画面（`/account/login?returnTo=…`）へ移動し、ログイン後は元のURLへ戻ります。カートのURLは履歴に残さず、ブラウザーの「戻る」でログイン画面へ引き戻されないようにします。
- ゲストカート（`frontend/src/guestCart.js` の追加処理、ログイン時の取り込み、取り込み再試行の画面）と `PUT /api/cart/guest-items` を削除します。
- 商品一覧・価格・在庫の公開APIは未ログインでも読めます。カートAPIと注文APIの認証要件は変えません。

## Alternatives

- ゲストカートをDB・Cookie・ブラウザー保存で永続化する: 匿名データの保持と取り込み時の競合処理が増え、ユーザーの決定（未ログインではカートを使わない）と合わないため採用しません。
- 未ログインでもカート画面を空で表示し、追加だけを止める: 何も入らないカートに見え、ログインが必要な理由が伝わらないため採用しません。
- カート画面の中にログインフォームを出す: 専用ログイン画面と見た目が揃わず、PRレビューで指摘されたため採用しません。

## Consequences / Validation

- 未ログイン中に選んだ商品はカートに残りません。ログイン後に改めて追加します。
- 取り込みAPIとその競合処理がなくなり、カートの更新経路は会員カートのAPIだけになります。
- 受取店舗変更（`selectStore`）にはゲスト用の分岐が残っています。同時に進むIssue #70が `selectStore` と `Cart.jsx`・`CartPage.jsx` を変更するため、本変更では触れていません。両方のマージ後の後続作業で、`guestCart.js`、`useShop.js` の `guestCart`・`guestPlan`・`rememberGuest`・`isGuest`、`types.js` の `guest` と `GuestCartPlan`、`Cart.jsx`・`CartPage.jsx` の `isGuest` 分岐を削除します（現在は到達しない分岐です）。
- `e2e/login-required-cart.spec.js` は実Java API・専用MySQL・実Cognito・Chromiumで、未ログインの追加がログイン画面へ移ること、カートAPIへの書き込みとDB行数の変化がないこと、ヘッダーのカートボタンと `/cart` が専用ログイン画面へ移ってカートが表示されないこと、「戻る」で元のページへ戻れること、`/cart` からログインすると同じページへ戻ること、ログイン後の追加が再読み込み後も実カートに残ること、取り込みAPIが削除されていることを確認します。成果物は `artifacts/login-required-cart/` に保存します。
