# 店舗受け取りの連絡先をアカウントへ移す

## Context

店舗受け取りの連絡先（受取人・電話番号・連絡先メール）は、カートごとに保存していた。カート画面で毎回入力を求めるため、同じ会員が複数のカートで同じ情報を入力し直す必要があった。カート画面には「商品と受取方法をご確認ください。」と手順表示があり、導線として不要になった。

## Decision

- 連絡先は会員アカウントに1件保存する（`member_pickup_contacts`、会員IDを主キー）。住所管理と同じ方式で、`/api/account/pickup-contact` の GET / PUT / DELETE で扱い、画面は「アカウント設定 > 受取連絡先」に置く。
- カートの表示と注文確定は、カート所有会員の連絡先を読んで使う。連絡先がない場合は空として扱う。
- カートにだけ保存していた連絡先の API（`PUT/DELETE /api/cart/details`）と画面入力は廃止する。既存の `cart_details` テーブルは削除せず、読み書きしない状態で残す。
- カートの手順表示（1 カート確認 / 2 店舗受け取り / 3 注文確認）と「商品と受取方法をご確認ください。」は表示しない。
- 「庭の計画を、暮らしの中へ。」の見出しを外し、「植物を探す」は「戻る」（左）に変更する。カート / 庭の買い物リストの切替は同じ行の右側へ移す。

## Alternatives

- カートに保存したまま表示だけ変える案は、注文ごとの連絡先がカートに依存し続けるため採用しない。
- 既存の住所（`member_addresses`）へ項目を追加する案は、住所（郵便番号・住所）と店舗受け取りの連絡先の意味が異なるため採用しない。

## Consequences

- 注文時の連絡先は、確定時点のアカウント連絡先を `order_details` に複写する。確定後にアカウントを変えても既存注文は変わらない。
- `cart_details` は読み書きされなくなる。削除は別の作業で、データ保持の判断を要する。
- 移行は V12 のテーブル追加のみ。既存カートの連絡先は移行しない（利用者は一度アカウントで入力する）。
