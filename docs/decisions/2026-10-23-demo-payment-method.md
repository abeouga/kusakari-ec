# 注文確認画面のデモ支払い方法

## Context

「注文内容を確認する」を押してもカートとほぼ同じ見た目のままで、受け取り店舗や支払いの確認段階であることが伝わらなかった。実決済・精算は対象外だが、購入の流れとして支払い方法を選ぶ段階は必要とされた。

## Decision

- 確認段階では編集可能なカート行を隠し、受け取り店舗（店舗名・住所・営業時間）、受取連絡先、支払い方法、注文商品を表示する。
- 支払い方法は `PAY_AT_STORE`（既定）、`CREDIT_CARD`、`PAYPAY`、`RAKUTEN_PAY` から選ぶ。`POST /api/orders` の `paymentMethod` を必須とし、既存の `order_details.payment_method` 列へ保存する。スキーマ変更はない。
- 決済事業者へは接続しない。カード番号などの支払い情報は入力欄を設けず、送信も保存もしない。
- 同じ `requestId` で支払い方法だけを変えた再送は `REQUEST_REUSED`（409）とする。受取連絡先の編集では保存済みの支払い方法を維持する。

## Alternatives

- 画面内だけで選択を保持する案：再読み込みや注文履歴で選択が失われ、注文記録と画面表示が一致しないため採用しない。
- カード番号入力付きのモックフォーム：実カード番号が入力される恐れがあり、デモで扱う必要のない機密情報を生むため採用しない。

## Consequences

- 旧フロントの `paymentMethod` なし注文要求は 400 となる。フロントとAPIは同時に更新する。
- 実決済を導入する場合は、決済事業者の結果（承認ID・状態）を別項目として持ち、この値は利用者の選択として扱う。
