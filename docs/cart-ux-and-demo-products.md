# カートUX・展示商品・庭サムネイル

## Context

2026-10-17。カートの囲みが重なり、専用ヘッダーへの切り替えで画面の統一感が失われていた。庭別一覧には視覚的な識別手段がなく、配置可能な植物商品も環境ごとに異なっていた。

## Decision

- ECの共通ヘッダーを使い、カートと庭の買い物リストをセグメントコントロールで切り替える。URL、ブラウザーの戻る、左右/Home/Endキーに対応する。
- 商品行・庭の行は区切り線で整理し、請求内容だけを背景色で強調する。
- 樹木2種・低木2種・草花2種の架空デモ商品をFlyway V5で一度だけ追加する。各店舗の初期在庫は60。既存の商品・在庫を更新しない。
- 6商品の固定ID、特徴、確定済み3Dパーツ構成をSQLに保存する。商品画像は実際の登録モデルを撮影したPNG。配置時に新しいモデルを生成しない。
- 庭のサムネイルは最新の生成履歴のAfter画像を優先し、次に現在のrevisionのCanvasキャプチャ、最後に現行配置から描く配置図を使う。履歴削除や配置変更は一覧のポーリングで反映する。
- CanvasのAlembic 0006で `garden_thumbnails` を追加。読み込み・保存が落ち着いた時に640×400px以内のPNGを保存する。写真モードでは写真と配置を合成する。撮影中の操作ハンドルは含めない。
- ECは自分の `/api/shopping-lists/{id}/thumbnail` から画像を取得し、Canvas側で所有者を確認する。一覧JSONには画像本体を含めない。

## Alternatives

カートと庭一覧の縦積み、庭ごとの購入カート、ブラウザーだけに保存するデモ商品は採用しない。未撮影の古い庭を無画像にせず配置図で表示する。サムネイルのために有料の画像生成を呼び出さない。

## Consequences

別環境で同じ商品を使うには、このECのV5・PNGと、対応するCanvasの3Dパーツを含むソースを配置し、通常のビルド・起動を行う。既存DBもV5が未適用なら追加される。再起動で在庫を補充しない。未コミットのため、別PCへ自動配布済みではない。

生成イメージは最後に生成した時点の画像であり、その後の配置変更を自動再生成しない。画像未生成かつ未撮影の庭は「庭の配置図」と明示する。ユーザーの庭や生成履歴を削除しない。

## Verification

実APIと専用MySQLを使ったChromium E2Eで、カート・商品管理・注文等の回帰10件が成功。サムネイル追加後に6商品の配置フローとサムネイル優先順位の2件を実行し成功（重複を除いて11ケース）。所有者分離のAPI確認6項目も成功。

- 6商品をドラッグ配置し、モデル構成・保存・再読み込みを確認。
- セグメント、キーボード、URL復元、モバイル幅、共通ヘッダーのログインを確認。
- 生成画像の優先、最新履歴への更新、履歴削除時のフォールバック、古いrevisionの拒否、不正画像、EC経由の画像一致を確認。
- サムネイルの生成履歴テストは専用DBの画像保存フィクスチャ。外部の有料画像生成は実行していない。
- 通常DBは変更前後の行数・ハッシュで既存業務データの維持を確認。通常環境には「6種類の植物を比べる庭」を作成し、6モデルを配置して保存した。

実行: `npx playwright test --config playwright.cart-ux.config.js`。画像・API JSONは `artifacts/e2e/cart-ux/`、通常環境の展示庭は `artifacts/cart-ux/normal-garden.json`。

通常DBと専用E2E DBで6商品のID・名前・価格・画像パス・特徴・3D構成が一致することを確認した。既存7庭のキャプチャも作成し、計8庭のサムネイルを取得できる。撮影前後のGardenDocumentは一致した。証跡は `artifacts/cart-ux/cross-database-products.json` と `thumbnail-backfill.json`。
