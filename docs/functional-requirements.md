# 機能要件61項目の対応表

更新日: 2026-11-16

## 実行と境界

- ECは `start.bat`、Canvasは隣接する `kusakari-canvas/start.bat` で起動します。ECは http://127.0.0.1:5186/ 、Canvasは http://127.0.0.1:5173/ です。
- ECがサービスの中心です。CanvasはECの商品選びを支える機能です。
- 業務画面は実API/MySQLを使用します。`useDemo`と`demoData`は撤去しました。再読み込み後も保存済みの状態を取得します。
- 共通ヘッダーはEC・Canvasとも認証済みならログインを非表示にし、管理者画面へのリンクは種別が `ADMIN` の場合だけ表示します（メールアドレスでは判定しません、#157）。
- ヘッダーの出店者リンクは認証済みの `SHOP_OWNER`・`SHOP_STAFF`・`ADMIN` だけに表示し、購入者（`USER`、`user01@example.com` を含む）・申請中のアカウント・未ログイン・認証確認中は非表示にします。会員の種別は[会員の種別とロールの値](member-roles.md)を参照してください。
- カートはログインした会員だけが使えます。未ログインでは商品一覧と商品詳細を閲覧でき、カートに追加しようとするとカートを変更せず専用ログイン画面へ移動します。ヘッダーのカートボタンと `/cart` はカートを表示せず専用ログイン画面へ移動し、ログイン後は元のページへ戻ります。決定は[未ログイン時のカート利用](decisions/2026-11-09-login-required-cart.md)を参照してください。
- アカウントのサイドバーは「マイページ」（アカウント情報・注文履歴・通知一覧）と「アカウント設定」（受取連絡先・パスワード変更・退会）に分けます。ログイン・新規登録・パスワードリセットはサイドバーに置きません。出店申請（申請後は出店申請状況）は、申請中のアカウント（`SHOP_OWNER_APPLICANT`）にだけ「出店をご検討の方」として表示します。
- `cognito` profileではCognito/Spring Securityによる認証と、利用者・担当店舗ごとのAPI認可を使用します。実User Poolを作成し、ECの専用ログインページから実認証します。Canvasの未ログイン時はECへ転送し、ログイン成功後は元の画面へ戻ります。通常起動はCognito必須です。設定不備は明示的に失敗します。[認証仕様](cognito-auth.md)を参照してください。
- 既存APIの価格・在庫・カート・注文・庭保存をモックやブラウザー保存へ置き換えません。
- 商品・在庫・受注・審査・通知は同じEC DBへ保存します。決済は Stripe のテストモードだけを範囲に入れます（実際のお金は動かしません。[残りの決定](decisions/2026-11-12-remaining-decisions.md)）。販売手数料（全店舗一律8%）は注文ごとに保存して注文実績に表示するだけで、請求・精算・差し引きはしません（[記録](decisions/2026-11-13-commission-and-closed-store-sales.md)）。外部メール配信・配送は対象外です。
- 管理者画面は会員管理を入口とし、メニューは会員管理・商品管理・カテゴリ管理・出店審査・店舗管理・組織管理・全注文管理です。運営ダッシュボードと手数料・精算管理の画面はありません。旧URL `/operator` と `/operator/settlements` は `/operator/members` へ移動します。
- 出店者画面のメニューは商品管理・店舗受け取り・注文実績・店舗一覧・店舗プロフィール・出店者通知で、オーナー・`ORG_ADMIN`・`MANAGER` にはアカウント・招待キーも表示します。サイドバー最上部の「戻る」ボタンで購入者トップへ移動します。出店者画面の入口は商品管理で、`/seller` と旧URL `/seller/messages` は `/seller/products` へ移動します。
- 商品一覧の「新しい商品」から `/seller/products/new` の商品追加画面へ移動します。ヘッダーとサイドバーを一覧と共用し、一覧には追加フォームを表示しません。追加画面で商品の店舗を選択し、保存成功時または左矢印付きの「戻る」ボタン（読み上げ名「商品一覧へ戻る」）で一覧へ戻ります。保存失敗時は入力を保持して追加画面に留まります。
- 新規出品は「商品情報 → 画像 → 庭オブジェクト → 確認」の4ステップとし、ステップ表記はボタンに見えないバー（現在のステップに `aria-current="step"`）で示し、確認画面の「出品する」で保存します。編集は商品情報・画像・庭オブジェクトの3タブへ直接移動し、「変更を保存」で更新します。商品番号は入力せず登録時にサーバーが自動採番し、編集時は表示のみで変更できません。カテゴリーは絞り込み付きのダイアログ、商品の店舗（在庫を登録する店舗）は画面内の地図モック（店舗の緯度・経度からピンを配置し、外部の地図API・タイルは読み込まない）と店舗一覧のダイアログで選びます。ダイアログはキーボードで操作でき、閉じると元のボタンへフォーカスが戻ります。画像は「画像」ステップで追加し、1枚目をメイン画像として庭オブジェクトのAI推定にも使います。植物の高さ（土際から最高点まで、鉢を含まない）は庭オブジェクトのステップだけで10〜1500cmの範囲で入力し、商品ページの高さ表示にも使います。サイズ・詳しい情報・モデル詳細は初期状態で折りたたみます。ウィザード内で前のステップへ戻るボタンは画面上部の「戻る」と区別するため「前の手順へ」とし、この操作やAI取り消しで入力を保持し、検証エラーのあるステップ・折りたたみへ移動します。詳しくは[植物特徴とCanvasのGLB部品構成](plant-model-listing.md)を参照してください。

## 対応表

購入者トップのヘッダー直下は、左側のコピーとCanvasへの導線を維持し、右側に購入者に見える商品を5秒間隔で横送り表示します。初期表示はオリーブがあればオリーブ、なければ一覧先頭です。以降は一覧順に循環し、商品ボタンは表示中の商品の詳細ダイアログを開きます。前後ボタンは画像の左右端に半透明で表示し、停止・再生ボタンは設けません。画像へのホバー中、キーボード操作中、ダイアログ表示中、ブラウザー非表示中は自動送りを停止します。動きを減らす端末設定では自動送りを行いません。商品構成が変わると表示を初期化し、1商品なら切替操作を省き、0商品なら商品なしの案内を表示します。

## Canvasから購入へのデータ

| Canvas素材ID | 材料コード | EC商品ID |
|---|---|---|
| tree_oak | plant.oak | canvas-oak |
| shrub_boxwood | plant.boxwood | canvas-boxwood |
| brick_paver | garden.brick | canvas-brick |
| bench_wood | garden.bench | canvas-bench |

数量は配置個数であり、敷き詰め面積から必要資材数を計算するBOMではありません。モデル表示寸法と架空の商品規格を明示しています。異なる植物を自動的に同じ商品とみなしません。

ECの画面には、材料JSONを受け取る画面（`/materials`）やトップページの「材料リストから探す」はありません（Issue #86）。

Canvasのバックエンドは `materialCode / quantity / unit` をECの `/api/materials/quote` へ送り、価格・在庫を照合します。このAPIは残します。Canvasの庭から購入する導線は庭の買い物リスト（[garden-shopping-lists.md](garden-shopping-lists.md)）です。カート追加には選択されたproductIdを使います。

環境変数はECの `VITE_KUSAKARI_CANVAS_URL`、Canvasの `VITE_KUSAKARI_EC_URL` です。各ルートの.envをViteのenvDirで読みます。変更後はフロントを再起動してください。

## 商品管理（出店者）

- 商品は1つの店舗に属し、在庫と公開状態（`inventory.publication_status`：PUBLISHED / HIDDEN / DELETED）は商品ごとに1つです。非表示は編集・再公開でき、削除は取り扱い終了で、再公開・非表示・在庫の変更はできません（409 `PRODUCT_ARCHIVED`）。商品・注文履歴は残します。運営者による停止（`products.suspended`）は別の属性で、出店者の再公開では解除できません。
- 一覧は `GET /api/seller/products?storeId=...` で取得します。商品名/SKUの検索、カテゴリ・状態の絞り込み、登録が新しい順/価格の安い順・高い順/商品名順、25件ごとのページ表示、個別・一括操作に対応します。選択は現在のページだけで、条件や店舗を変えると解除します。
- 公開状態は目のアイコンつきボタンで、押すと公開中・非表示を直接切り替えます。操作欄は鉛筆アイコンの編集とゴミ箱アイコンの削除です。削除と一括変更は確認画面を出します。
- 状態の変更は `PATCH /api/seller/products/status` で、店舗・1〜25件の重複しない商品ID・変更後の状態を指定し、全件を検証してから同じトランザクションで反映します。在庫の行は注文確定と同じ商品ID順にロックします。
- 在庫の更新は一覧の「在庫を編集」から `PUT /api/seller/products/{id}/stock` で行い、画面に表示した在庫数（`expectedStock`）と照合します。変わっていれば409 `STOCK_CHANGED` で保存せず、最新の在庫数で確認し直します（EC-S05 5b）。在庫だけの画面はありません。
- 購入前に非表示・削除になった商品はカートに残りますが、注文できません。
