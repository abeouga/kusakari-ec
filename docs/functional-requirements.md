# 機能要件61項目の対応表

更新日: 2026-10-20

## 実行と境界

- ECは `start.bat`、Canvasは隣接する `kusakari-canvas/start.bat` で起動します。ECは http://127.0.0.1:5186/ 、Canvasは http://127.0.0.1:5173/ です。
- ECがサービスの中心です。CanvasはECの商品選びを支える機能です。
- 業務画面は実API/MySQLを使用します。`useDemo`と`demoData`は撤去しました。再読み込み後も保存済みの状態を取得します。
- 共通ヘッダーはEC・Canvasとも認証済みならログインを非表示にし、管理者画面へのリンクは `test.admin@example.com` かつ `ADMIN` 権限の場合だけ表示します。
- ヘッダーの出店者リンクは認証済みの `SELLER`・`ADMIN` だけに表示し、一般会員（`test.user@example.com` を含む）・未ログイン・認証確認中は非表示にします。
- アカウントのサイドバーは「マイページ」（アカウント情報・注文状況・通知一覧）と「アカウント設定」（住所管理・パスワード変更・退会）に分けます。ログイン・新規登録・パスワードリセット・配置素材の商品候補を混在させず、出店申請は一般会員だけに表示します。既存の各URLと機能は維持します。
- `cognito` profileではCognito/Spring Securityによる認証と、利用者・担当店舗ごとのAPI認可を使用します。実User Poolを作成し、ECの専用ログインページから実認証します。Canvasの未ログイン時はECへ転送し、ログイン成功後は元の画面へ戻ります。通常起動はCognito必須です。設定不備は明示的に失敗します。[認証仕様](cognito-auth.md)を参照してください。
- 既存APIの価格・在庫・カート・注文・庭保存をモックやブラウザー保存へ置き換えません。
- 出店者HTML10画面を参考に共通のReact画面を作成しました。元HTMLを保持し、CDNのTailwindや元の個別DOMスクリプトは使用しません。
- 商品・在庫・受注・審査・通知は同じEC DBへ保存します。実決済・外部メール配信・配送・手数料・精算は対象外です。
- 管理者画面は会員管理を入口とし、重複していたアカウント管理リンクを削除しました。運営ダッシュボードと手数料・精算管理は削除し、旧URL `/operator` と `/operator/settlements` は `/operator/members` へ移動します。
- 出店申請は一般会員のメニューから利用できます。お問い合わせ画面とアカウント管理リンクを削除し、サイドバー最上部の「戻る」ボタンで購入者トップへ移動します。旧URL `/seller/messages` は `/seller` へ移動します。
- 商品一覧の「新しい商品」から `/seller/products/new` の商品追加画面へ移動します。ヘッダーとサイドバーを一覧と共用し、一覧には追加フォームを表示しません。追加画面で登録先の店舗を選択し、保存成功時または「商品一覧へ戻る」で一覧へ戻ります。保存失敗時は入力を保持して追加画面に留まります。
- 新規出品は「商品情報 → 庭オブジェクト → 確認」の3ステップとし、確認画面の「出品する」で保存します。編集は商品情報・庭オブジェクトのタブへ直接移動し、「変更を保存」で更新します。サイズ・詳しい情報・モデル詳細は初期状態で折りたたみ、画像と入力欄、3Dプレビューと設定はPCで横並びにします。高さは共通状態で保持し、土際から最高点まで（鉢を含まない）の値を双方で使用します。戻る操作やAI取り消しで入力を保持し、検証エラーのあるステップ・折りたたみへ移動します。

## 対応表

購入者トップのヘッダー直下は、左側のコピーとCanvasへの導線を維持し、右側に受取店舗の公開商品を5秒間隔で横送り表示します。初期表示はオリーブがあればオリーブ、なければ一覧先頭です。以降は一覧順に循環し、商品ボタンは表示中の商品の詳細ダイアログを開きます。前後ボタンは画像の左右端に半透明で表示し、停止・再生ボタンは設けません。画像へのホバー中、キーボード操作中、ダイアログ表示中、ブラウザー非表示中は自動送りを停止します。動きを減らす端末設定では自動送りを行いません。店舗や商品構成が変わると表示を初期化し、1商品なら切替操作を省き、0商品なら商品なしの案内を表示します。

## Canvasから購入へのデータ

| Canvas素材ID | 材料コード | EC商品ID |
|---|---|---|
| tree_oak | plant.oak | canvas-oak |
| shrub_boxwood | plant.boxwood | canvas-boxwood |
| brick_paver | garden.brick | canvas-brick |
| bench_wood | garden.bench | canvas-bench |

数量は配置個数であり、敷き詰め面積から必要資材数を計算するBOMではありません。モデル表示寸法と架空の商品規格を明示しています。異なる植物を自動的に同じ商品とみなしません。

`/materials#canvas-items=...` にJSONをURLエンコードして渡します。送る項目は `materialCode / quantity / unit` のみです。EC側で1〜50種類、数量1〜99、unit=piece、コード形式、重複、未知項目、データ長を検証します。非対応コードは既存APIのUNMAPPEDとして表示します。99個を超える配置は購入候補への移動前にエラーを表示します。

価格・在庫は店舗選択後にECの `/api/materials/quote` で照合します。カート追加には選択されたproductIdを使います。受け渡しだけではカート追加や注文は発生しません。

環境変数はECの `VITE_KUSAKARI_CANVAS_URL`、Canvasの `VITE_KUSAKARI_EC_URL` です。各ルートの.envをViteのenvDirで読みます。変更後はフロントを再起動してください。

## 商品入力の補助（2026-10-19）

商品追加・編集で高さ・鉢径・樹齢・耐寒温度と庭オブジェクトの数値にスライダーを併設する。
手入れレベル・葉の密度は説明付きの3段階スライダー。価格・在庫は数値入力を継続する。
AI設定は商品名・説明・学名・写真1枚から庭オブジェクトの特徴だけを推定し、フォームへ反映する。
未入力の高さはAI推定と表示する。反映前へ戻すことができ、保存は従来の商品APIを使用する。

### 商品写真（2026-10-19）

商品写真はPNG/JPEG/WebPを選択して追加する。URL入力欄は表示しない。商品追加の詳しい情報は生産者名・学名・科名に限定する。出品者Tipsは撤去済み。編集ボタン、購入者表示、専用API、専用の文章項目を商品APIから削除した。日照等の検索用属性は維持する。保存済みの旧DB列・データは削除しない。


## 店舗別の商品公開管理（2026-10-19）

### Context

商品本体は全店舗共通、在庫は店舗別です。従来の商品削除と公開停止は同じ全体停止APIを使っており、非表示商品の再公開や店舗単位の操作ができませんでした。

### Decision

- 在庫行に `publication_status`（PUBLISHED / HIDDEN / DELETED）を保存します。非表示は管理画面で編集・再公開でき、削除は選択店舗の取り扱い終了として扱います。商品・在庫数量・注文履歴は保持します。
- 商品一覧の公開状態は目のアイコン付きボタンとし、押すと公開中・非表示を直接切り替えます。操作欄は鉛筆アイコン付きの編集とゴミ箱アイコン付きの削除を表示します。削除と一括変更は確認画面を維持します。
- 出店者の一覧と在庫画面は専用APIで公開中・非表示を取得します。一覧で不要な生成済み3Dメッシュは返さず、編集用のモデルパラメータは保持します。管理店舗は購入者のカート店舗と独立します。商品名・価格は従来どおり共通情報です。
- 一覧は商品名/SKU検索、カテゴリ・状態の絞り込み、新しい順/価格昇降順/商品名順、25件のページ表示、個別・一括操作に対応します。選択は現在ページのみで、条件や店舗を変えると解除します。
- `GET /api/seller/products?storeId=...` と `PATCH /api/seller/products/status` を追加します。更新は店舗、1〜25件の重複しない商品ID、変更後の状態を指定し、全件検証後に同一トランザクションで反映します。
- 購入者向けProductViewのactiveは商品全体の有効状態と選択店舗の公開状態を両方満たす場合だけtrueです。Canvas照合、庭の購入候補、カートの購入可否にも適用します。注文確定と状態更新は店舗在庫を商品ID順にロックします。
- 旧DELETE APIは既存クライアントとの互換性のため全体停止のまま保持します。出店者UIは呼びません。V7移行では過去に全体停止された商品を再公開しません。

### Alternatives

全店舗共通の非表示と削除はユーザーの運用に合わないため採用しません。物理削除と削除済み商品の復元画面も今回の対象外です。

### Consequences / validation

購入前に非表示になった商品は既存カートに残りますが注文できません。他店舗の在庫や公開状態は変わりません。認証・店舗所有権は今回追加しておらず、既存のローカルデモ境界を維持します。

`e2e/seller-products.spec.js` は実API/MySQLを使用し、検索・並び替え・ページ・一括操作・店舗分離・再読込後の状態、全件取消、購入不可、注文履歴保持を検証します。注文確定と非表示の競合テストは、同時更新時にも成立した注文と在庫減算が一致し、非表示確定後に新たな注文が成立しないことを確認するために設けます。テスト固有の商品とセッションだけを使用します。

実装構成・移行・試験手順は [業務バックエンド](business-backend.md) を参照してください。
