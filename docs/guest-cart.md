# ゲストカート

## Context

未ログインでも商品を選び、カートを確認してからログインできるようにする。ユーザー指定により、未ログイン中のカートは永続化しない。

## Decision

- ゲストカートはEC画面のReact状態だけで保持する。DB、Cookie、localStorage、sessionStorage、IndexedDB、URLへ商品や数量を保存しない。商品情報・在庫は実際の公開カタログAPIから読み、金額は見積もりとして表示する。
- 同じ画面内の遷移では状態を維持し、再読み込み・タブ終了・ECからの離脱で消える。専用ログインページへは画面内で移動する。Cognitoの外部画面への移動ではゲスト状態を維持しない。
- 「注文内容を確認する」と「注文を確定する」の双方で実セッションを確認する。未認証なら専用ログイン画面を表示する。注文APIの認証要件を緩めない。
- パスワードログインの成功後だけ、選択数量を既存の会員カートへ加算する。引き継ぎ先が空ならゲストの受取店舗を使い、空でない会員カートと店舗が異なる場合は変更せず、店舗の選び直しを案内する。
- 認証必須の `PUT /api/cart/guest-items` は数量の絶対値とrevisionを受け、会員カートをロックする。全商品の公開状態・在庫・数量上限・種類数・店舗を検証してから1トランザクションで更新する。失敗時は一部の商品だけを保存しない。価格・最終金額・注文時の在庫は引き続きECサーバーが確定する。
- 通信結果が不明なときは画面内に引き継ぎの目標数量を残す。再試行では実カートを照合し、反映済みなら再加算しない。再読み込みすればこの一時情報も消える。

## Alternatives

匿名カートのDB保存、ブラウザー保存、Cookieへの詰め込み、未認証の注文は採用しない。既存の認証済みカートと注文の保存方式は維持する。

## Consequences / Validation

画面に一時カートが消える条件を表示する。受取連絡先はログイン後に入力する。外部認証への移動や再読み込みを挟んだゲスト選択の復元は行わない。実決済の追加は対象外。

`e2e/guest-cart.spec.js` は実Java API・MySQL・Cognito・Chromiumを使う。未ログインでの追加・変更・削除、DB行数不変、保存領域不使用、再読み込みによる消去、未認証の引き継ぎ・注文拒否、ログイン後の引き継ぎ、入力不正・revision競合時の全体不変を確認する。応答喪失の試験だけは実APIの更新後にブラウザー通信を中断する障害注入を行い、再試行で数量が重複しないことを確認する。正常系APIをモックしない。
